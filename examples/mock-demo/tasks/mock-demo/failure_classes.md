# Failure classes: mock-demo

Symptom-class to mechanism guide, consumed as `{FAILURE_CLASS_GUIDE}` in
the editor prompt (PROGRAM.md §4b). Classes are named by symptom family;
the mechanism column says where to look, not what to write.

| class | symptom looks like | mechanism |
|---|---|---|
| unsupported-claims | figures or quotes with nothing backing them | the document workflow lacks an evidence step |
| open-choices | reader left with an option list and no guidance | the document never commits to a recommendation |
| unchecked-delivery | shipped artifact has a defect one glance would catch | nothing forces an inspection before handoff |
| naming-drift | one component under several names in one document | no terminology discipline across sections |
| abstract-explanations | behavior described but hard to follow | explanation style leans on description, not demonstration |
| restart-discontinuity | animation jumps at the moment it restarts | the loop boundary: closing state vs opening state |
| dimension-drift | rendered size differs from the spec sheet | output geometry is never reconciled with the spec |
| stage-desync | parallel elements move at visibly different times | per-element timing is set independently within a stage |
